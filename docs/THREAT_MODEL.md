# Preview security and privacy threat model

This is a code-level threat model for the TampaBayBot Pages preview, its backend Worker, and optional model and GIS integrations. It describes the October 2026 source tree, including the deterministic housing guide. It is not a penetration test, a review of Cloudflare account settings, or proof that the hosted preview runs this commit. [Security reporting](../SECURITY.md) and [operations](OPERATIONS.md) cover incident handling and deployment settings.

## Data and trust boundaries

| Boundary | Data crossing it | Code evidence and limits |
| --- | --- | --- |
| Browser to Pages | Page and static directory requests; submitted chat questions and property requests when those tools are used | The static guide and directory filter in `pages-demo/src/CrisisGuide.tsx` and `HousingHelp.tsx` compute from bundled data in page memory. Loading the hosted page still contacts Cloudflare. The chat form in `pages-demo/src/App.tsx` and property form send JSON to `/api/*`. |
| Pages Function to backend Worker | Allowed API requests and classic Next routes | `functions/api/[[path]].js` allowlists API paths and methods and forwards through the `BACKEND` service binding. `functions/[[path]].js` forwards classic routes. The deployment must bind the intended private Worker and verify its public-route settings; repository code alone does not establish a hosted account's routing. |
| Backend to operational D1 | Rotating HMAC-derived client keys, rate counters, active leases and aggregate metrics | `src/lib/operations/control.mjs` and `schema.mjs` do not write question or address text or raw IPs to D1. Expired rows are deleted on later requests or monitor runs, so the seven-day metrics target is not immediate deletion. Shared mode needs valid D1 and a server-side limit secret; local mode has no cross-instance rate coordination. |
| Backend to optional model | Current eligible question; selected public-source IDs, titles and exact excerpts | `src/lib/llm/selection.mjs` prepares the bounded prompt. The question is **not generally redacted**. `LLM_PROVIDER=none` avoids a model call; enabled Cloudflare Workers AI or HTTP providers can process eligible questions. A hosted Worker cannot reach a visitor's local Ollama through the visitor's loopback address. A local Ollama daemon can itself be configured to use a cloud model. |
| Backend to public GIS and other websites | Entered address, then selected address/coordinates and queries needed for property and development results | `src/lib/geospatial/index.mjs` sends address searches to configured public services. Opening the optional map, government resources or other links creates separate third-party traffic. The app cannot set those services' retention rules. |
| Publisher material to evidence and answers | Downloaded HTML/PDF/CSV/JSON text and metadata | Ingestion normalizes bounded source content; retrieval excludes recognized instruction text. Quotes and citation IDs must match retrieved source chunks. Publisher facts may still be outdated, wrong or maliciously worded. An available URL is not factual verification. |

The application has no resident account or document-upload feature. In the inspected code, questions, guide selections, conversation turns and addresses are not stored in browser local/session storage or the application database. They can remain in page memory while the tab is open. User-initiated copy, download and print actions can leave device copies. Hosting, GIS, model provider and network logs or caches are separate; the source tree cannot establish their actual retention or the hosted preview's configuration. The generated Worker config disables application observability to minimize captured data, reducing incident visibility; it does not prove that Cloudflare or other parties keep no logs.

## Threats, controls and remaining risk

| Threat and entry point | Current control | Residual risk and operator action |
| --- | --- | --- |
| **Privacy leakage:** a resident includes a name, case number, address or credential in a question. The Pages and Worker path, and possibly a model, receive it. | Forms discourage sensitive detail. `src/lib/guardrails/privacy.mjs` blocks a narrow set of account/credential patterns; no general redaction is claimed. Runtime configuration and model credentials stay server-side. The model receives selected excerpts rather than complete corpus or raw previous turns. App logs use event codes and D1 stores keyed usage data and aggregates. | Names and case narratives can pass the narrow screen. An enabled provider can log or retain them, and hosted page/API traffic can enter platform logs. Verify host/provider settings and live configuration before release. Use synthetic data in testing and incident records; do not put resident input in tickets or logs. |
| **Malicious retrieval content:** a publisher page or compromised source contains commands to ignore policy, expose secrets, change eligibility or add a citation. | Source acquisition and normalization are bounded. `src/lib/retrieval/eligibility.mjs` quarantines recognized instruction patterns; `src/lib/llm/selection.mjs` labels question/evidence as untrusted data. Model output is restricted to exact supplied quotations/selections. `src/lib/citations/evidence.mjs` validates source and chunk identity, literal quotes, safe source URL and citation IDs. | Pattern screens cannot recognize every instruction or deceptive factual statement. A real publisher page could be compromised, and an exact quote can still be misleading or stale. Review source diffs before publication, monitor freshness, and require agency confirmation for consequential advice. |
| **Resource exhaustion:** automated clients flood chat, GIS or model endpoints with large or slow requests. | Pages and Worker route checks, bounded JSON readers, deadlines, shared D1 request/concurrency limits, outbound budgets, model quotas and response-size limits reduce work per request. Non-loopback public APIs refuse local mode; static directory browsing needs no backend or AI. | Edge traffic, bandwidth and platform costs start before Worker admission. Loopback local mode has no shared cross-instance limit; misconfigured shared controls refuse service. Test rate responses and cost caps in the actual host; keep static emergency resources available during backend incidents. |
| **Unsafe advice:** a chat answer or crisis plan is read as legal advice, eligibility approval, shelter availability or a certain deadline. | The housing guide uses fixed on-page rules and official navigation links. It does not compute an individual deadline or promise an opening. RAG answers separate cited source statements, interpretations and unknowns; insufficient, stale or conflicting evidence uses uncertainty and official fallbacks. Citations are checked against registered chunks. | Automation cannot verify live capacity, legal application to an individual, completeness or accessibility in every circumstance. Qualified Florida housing/legal reviewers and local providers must review eviction wording and referrals; residents should confirm current details directly. |
| **Credential or endpoint exposure:** a public bundle, error or model prompt discloses a runtime key or private URL. | Provider endpoints/keys are parsed only from server runtime configuration. Public `VITE_*`/`NEXT_PUBLIC_*` variables must not hold secrets. Provider responses are bounded, redirects are refused, and public errors do not include raw provider bodies. Source/commit secret scanning is part of the release workflow. | An operator can still misconfigure hosting, commit a secret, expose a private Worker route, or give a custom adapter more data. Verify deployed bindings/routes and rotate confirmed exposed credentials. Secret scanning detects patterns, not every credential; the current full-history gate remains unresolved. |

## Reproducible checks and gaps

From a source checkout, `npm test` covers request/response controls, operations, retrieval, prompt and citation guards, housing-crisis rules and synthetic provider behavior without production credentials or a live model. `npm run test:pages` covers the Pages proxy and static guide. Browser privacy and mobile checks live in `pages-demo/tests/privacy-browser.spec.mjs` and `tests/e2e/privacy.spec.ts`; run their documented Playwright commands after building. `npm run security:deps` checks dependency advisories, and `npm run security:scan` checks for secrets; scans depend on their local tooling and advisory data. A stable October 20 secret scan reported zero current-tree matches and 27 reachable-history detector matches, with status `findings_require_review`. The history matches require triage; no passing full-history result is claimed. None of these tests verifies Cloudflare account logging, provider retention, live GIS accuracy, deployed rate behavior or the usefulness of advice for a real resident.

Before widening public access, use an operator-owned deployment to check the actual Pages-to-Worker binding and private routes, no-store and security headers, shared D1 limits and `Retry-After`, provider enablement and retention, safe error responses, platform log settings, emergency directory independence, and abuse/cost alerts. Keep the [release-readiness record](RELEASE_READINESS.md) scoped to the tested version and date. Do not infer complete security from passing automated tests.
