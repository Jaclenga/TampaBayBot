# Verifying housing-crisis resources

The [static resource catalog](../pages-demo/src/housing-resources.json) serves the Cloudflare Pages directory and deterministic crisis plans. It remains accessible without Workers AI, D1 or the backend Worker. The catalog is a set of checked public navigation records, not a live vacancy, funding, appointment or eligibility feed. Its [record-level provenance notes](../pages-demo/src/HOUSING_RESOURCES.md) identify the sources checked in the current revision.

## Record meaning

Each record identifies an organization and program, crisis categories, geographic coverage, a short description, eligibility and restrictions, an official HTTPS website, a source URL, and public contact information. An `intakeUrl` or `serviceHours` is included only when a source explicitly supports it. Municipality restrictions are separate from county coverage; a City of Tampa program must not appear as a countywide entitlement.

`verifiedAt` means a contributor checked the cited public page and contact listing on that calendar date. `verificationStatus` distinguishes `source_checked`, `needs_recheck` and `source_unavailable`. It does not mean the contributor phoned the agency. `availabilityStatus` distinguishes `unknown`, `confirmed_open`, `temporarily_closed` and `discontinued`. Use `confirmed_open` only for an explicitly verified current program or intake state, with a source and date. A published phone number, application instructions, or a working web page alone does not establish open funding, a shelter bed, a waitlist position or approval. If a closure or discontinuation is reported, retain its source and date rather than silently deleting the history.

Changing service and intake contacts use a 30-day `refreshDays` interval; stable court and public legal-information pages use 90 days. These are review targets, not guarantees of accuracy for the entire interval. A record past its interval is stale and must be labeled for recheck. Plans first use recently checked records. If none match, an older `source_checked` contact may be shown for direct verification when its check is no more than 365 days old; it is copied into the plan with `needs_recheck` status and a warning, never presented as current availability. Closed, discontinued, originally `needs_recheck`, and source-unavailable records remain excluded from plans. The full directory may show stale listings with clear warnings and official links. A successful page fetch never upgrades `availabilityStatus` automatically.

## Contributor workflow

1. Find the publisher's official page or the service provider's own site. Use a direct program or intake page when available. Confirm the organization, program name, area served, public contact and the specific category of help.
2. Check eligibility and restrictions in the publisher's wording. Separate City limits, county coverage, referrals, direct shelter intake, applications and general information. Avoid claims about legal rights or deadlines unless a current authoritative source and required context support them.
3. Record the official URL and the page that supports the listed contact as `sourceUrl`. Add a direct `intakeUrl` and hours only when verified. Use `unknown` availability unless the cited source establishes a current status; do not infer it from a page title or a previous application window. If official pages conflict, document both and withhold the disputed referral or eligibility claim until the publisher resolves it.
4. Set `verifiedAt`, `verificationStatus`, `availabilityStatus` and `refreshDays` for that specific record. Update the provenance notes with cross-page checks, unreachable links and caveats. Recheck all changed records before rebuilding Pages; do not relabel untouched records with today's date.
5. Run the resource data tests, crisis evaluation suite and Pages browser test with the API disabled. Manually open key official links on a phone-size browser and verify copy/print, language and emergency access. A crawler response alone does not prove how a public browser will behave.

Do not copy private case details, intake submissions, client names, unlisted numbers or source-page prose into the catalog. Never add an unverified shelter opening or funding amount. Source review can identify an error in a listing; correcting the listing does not change the separately reviewed RAG corpus. See [source updates](SOURCE_UPDATES.md) for that pipeline and [safety limitations](SAFETY_AND_LIMITATIONS.md) for public-use boundaries.
