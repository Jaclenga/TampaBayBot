# Evaluation datasets

JSON inputs for evaluation live in this directory. Narrative navigation cases are defined directly in [benchmarks.mjs](../benchmarks.mjs), shared by the evaluators and guardrail tests. Evaluator code remains in the parent directory and `../suite/`.

| File | Purpose | How it is maintained |
| --- | --- | --- |
| [ground_truth_questions.json](ground_truth_questions.json) | The 20 user-provided questions, in their original order. This is a question-only list with no reference answers or scoring labels; it is not yet wired into an automated suite. | Preserve the question text as supplied. |
| [quality-benchmark.json](quality-benchmark.json) | Authored reference claims, exact claim hashes and allowed source/chunk support for the quality suite. | Review labels against the retained corpus before changing expectations. |
| [program-recall-benchmark.json](program-recall-benchmark.json) | A bounded program inventory, questions and expected applicable-program sets for `npm run eval:recall`. | Review program evidence and applicability labels together. |
| [answer-reliability.json](answer-reliability.json) | Forty-four fictional question-answer cases and a self-contained synthetic source fixture for offline answer reliability checks. Each case records expected behavior, permitted supporting passages, prohibited claims, clarification, uncertainty, and next-step expectations. | Review the authored support and negative claims when changing retrieval or answer policy; `.invalid` fixture links are never live resources. |
| [routing-citation-benchmark.json](routing-citation-benchmark.json) | Seventy-two fictional resident questions, nine each for eviction, housing assistance, eligibility, zoning, property information, emergencies, ambiguity, and unsupported requests. Expected labels cover subject routing, conservative responses, citation and source policy, and crisis-guide referral. | Run the offline regression suite after changing routing, retrieval, answers, citations, or crisis resources. Review behavioral labels against product policy and the synthetic fixture; do not add factual answers from memory. |

## Routing and citation benchmark labels

The benchmark uses the `synthetic-civic-preview` fixture embedded in `answer-reliability.json`. Its short passages and `.invalid` links are test evidence only. `source_ids_any` names **fixture** source IDs and always requires one of them in response evidence, including when the answer remains conservative. This catches a lost retrieval result that would otherwise look like a safe nonanswer. `official_source_required` requires first-party evidence whenever evidence is present, and `citation_required_if_claims` requires a citation when the response claims to have answered. An empty `source_ids_any` means the fixture does not establish a specific source for that request; it does not authorize an uncited factual answer. Real source registry availability and program rules are separate from this oracle.

`refuse: true` means the response must decline to make the requested determination or promise while still offering safe navigation where possible. It is not a request for silence. `forbidden_claims` are case-specific, case-insensitive regular expressions checked against the answer and its explanation. A failure means the response contains a prohibited wording, while a pass does not prove every possible unsupported claim is absent. `needs_address` and `needs_jurisdiction` indicate the required information when it is the next decision point; an official-judgment response may take priority over a property address request. `status: "answered"` appears only for navigation supported by the synthetic passage; no label supplies a personal eligibility decision, parcel designation, court deadline, open bed, current funding, or live application status.

`crisis_situation` and `resource_ids_any` refer to the separate deterministic housing-crisis guide and IDs in `pages-demo/src/housing-resources.json`. The synthetic answer fixture and that directory have different evidence roles. A crisis resource match establishes a relevant referral path, not current intake, a bed, an award, or a legal conclusion. Cases omit a crisis label when the question lacks enough urgency or detail to select one.

Generated reports remain in `../results/`, `../suite/results/` and, for program recall, `work/evals/recall/` at the project root. Human review materials remain in `../human-audit/`.
